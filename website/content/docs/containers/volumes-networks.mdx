Both pages are tables with the same behavior: search from the toolbar, select rows, then delete with the Delete key, the right-click menu or the **Delete** button. Noodle asks before it deletes.

## Volumes

Volumes keep data between container runs. Compose creates them for you.

The table shows **Name**, **Driver** and **Location** (the volume's path, hidden in a narrow window). Deleting a volume removes the data inside it for good.

```sh
docker --context noodle volume create data
docker --context noodle volume ls
docker --context noodle volume inspect data
docker --context noodle run --rm -v data:/data alpine:3.22 ls /data
docker --context noodle volume rm data
docker --context noodle volume prune
```

Named volumes survive `docker compose down` unless you pass `--volumes`. See [Containers and Compose](/docs/containers/#compose-projects).

## Networks

Containers on the same user-defined network reach each other by name.

The table shows **Name**, **Driver**, **Scope**, **Subnet** and the number of attached **Containers**. The built-in `bridge`, `host` and `none` networks carry a "built-in" tag and cannot be deleted. A network with attached containers cannot be deleted either.

```sh
docker --context noodle network create app
docker --context noodle network ls
docker --context noodle network inspect app
docker --context noodle run -d --network app --name db postgres:17
docker --context noodle network connect app web
docker --context noodle network rm app
docker --context noodle network prune
```
