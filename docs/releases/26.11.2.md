# Noodle 26.11.2

Docker-compatible containers and local AI models on Apple silicon, in one small native Mac app. It is a beta.

## New in 26.11.2

- A welcome on first launch. Pick Models, Containers or Runners, then get each one ready from one screen: download a starter model, connect the Docker tools, add a repo. It shows once; Set Up Noodle still opens the Docker assistant.

## Install

```sh
brew install --cask ansumanshah/tap/noodle
```

Homebrew 7 asks you to trust a third-party tap first. If it refuses, run `brew trust ansumanshah/tap` and repeat the install.

Or download `Noodle-26.11.2.dmg` below, open it and drag Noodle to Applications. Then run `noodle setup`.

Built for Apple silicon Macs on macOS 26 or later. It has only been run on a Mac mini M4 with macOS 27.2.

## What is in it

- **Containers.** The `docker` CLI works against Noodle (`docker run --rm alpine echo hello`; setup makes Noodle your Docker context when no other engine is running, otherwise add `--context noodle` or run `noodle setup --use`): containers, images, volumes, IPv6 networks, Compose, Buildx and builds. amd64 images run through Rosetta. Containers get `*.localhost` names with local HTTPS. Single-node Kubernetes (`noodle kubernetes`) and Linux machines (`noodle machine`) are included.
- **Local names, no ports.** Containers and Compose services answer at `NAME.localhost` and `NAME.noodle.local` on ports 80 and 443, with no root and no hosts-file edit. `noodle names add api.myapp 3000` gives a dev server already running on your Mac a name too.
- **Models.** `noodle model run qwen3.5-4b` downloads a model and chats. GGUF and MLX models run through one process, served on a local OpenAI-compatible endpoint with a key. `docker model` and Compose `models:` use the same engine.
- **Runners.** GitHub Actions jobs run on this Mac, each in a fresh runner removed when the job ends. The Runners section has four pages: Overview (on or off, jobs running now, and why new jobs are being held when disk or memory is low), Repos (pause, resume, check workflows, remove), Jobs (history with a log tail) and Caches (size per repo with a Clear button). From the terminal: `noodle runners add owner/repo`, `noodle runners pause owner/repo`, `noodle runners resume owner/repo`, `noodle runners cache`, `noodle runners doctor`, `noodle runners toolchains` and `noodle runners clean`.
- **Command line.** `noodle help` and `noodle <group> help` list every command, and `noodle help --json` prints the same table for scripts. Exit codes are 0 for success, 1 for a failure, 2 for a usage error and 3 when the engine is not running. With `--json`, prose goes to stderr and stdout carries one JSON document.
- **Apps.** The Apps page installs AI apps from a catalog in one click (Open WebUI, AnythingLLM and n8n). Open WebUI and AnythingLLM come set up to use your local models.
- A native window and menu bar item. App updates are off until a signed update feed is configured.

## Numbers

Same Mac mini M4, 4 vCPUs and 2 GiB per engine. A `docker run --rm alpine true` took a median of 15.0 ms on Noodle, 48.1 ms on Kiri 0.2.2, 130.3 ms on Docker Desktop 29.9.3 and 171.6 ms on OrbStack. The daemon used 8.6 MB while the VM slept. Noodle lost the build rows in that run and cold pulls to Kiri. Ollama 0.40.16 decodes small models faster than Noodle on this Mac. The full numbers are on the [benchmarks page](https://getnoodle.dev/docs/benchmarks/).

The last full Docker CLI run on macOS 27.2 had 599 cases: 591 passed, 3 failed and 5 were skipped. The 3 failures have since been fixed and pass when run alone; the full run was not repeated.

## Known limits

- The device policy of the privileged-container VM has had no independent security review. Do not use Noodle as a sandbox for untrusted code.
- macOS 26 has not been run. Everything in these notes was verified on one Mac mini M4 with macOS 27.2.
- Builds are not reproducible, so source availability does not verify the DMG.
- Recovery after power loss is untested.
- A Mac process and a container appending to the same bind-mounted file can lose lines.
- `docker model` and Compose `models:` are implemented; their end-to-end cases are pending.
- No update feed is configured, so upgrade through Homebrew (`brew upgrade --cask noodle`).
- Services bound only to the Mac's `127.0.0.1` cannot be reached from `host.docker.internal` by privileged containers or over UDP.
- Intel Macs, Linux and Windows hosts are not supported.
