# e2fsprogs formatter

New data disks are formatted by the macOS `mke2fs` built from upstream e2fsprogs 1.47.4. The build script downloads the upstream release archive at <https://mirrors.edge.kernel.org/pub/linux/kernel/people/tytso/e2fsprogs/v1.47.4/e2fsprogs-1.47.4.tar.gz>, verifies SHA-256 `da274408bebbfd13a5a2fc3cfc66e3ffff17c48534673aa67f88d49b99123b96`, and builds with `--disable-nls --disable-e2initrd-helper`. Upstream publishes the digest in its [signed checksum list](https://mirrors.edge.kernel.org/pub/linux/kernel/people/tytso/e2fsprogs/v1.47.4/sha256sums.asc). The application bundle includes the upstream `NOTICE` alongside the binary and configuration. The same source archive is published with each release as `Noodle-<version>-e2fsprogs-source.tar.gz` (`scripts/release.sh source`), or bundled when built with `NOODLE_E2FSPROGS_SOURCE=bundle`.

The upstream notice describes GPL-2.0, LGPL, BSD and MIT components. The formatter is used only for a newly created disk; an existing disk is never passed to it. It creates a 16 MiB fully initialized journal and uses ext4's lazy inode-table initialization on the new sparse image. On this machine, formatting a fresh 64 GiB image allocated 21.42 MiB; sustained write performance has not been measured. Linux ext4 replays its journal when mounting after an unclean stop. Journal replay is not a backup or a repair for unrelated corruption, and it does not make application data durable without synchronization.
